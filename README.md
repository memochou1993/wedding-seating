# wedding-seating

2026.10.25 林府文定午宴（聖雅典・威尼斯 40+2 桌）的座位表網頁。
風格與花框沿用 `../wedding-signs` 的告示牌。

- 賓客版：https://memochou1993.github.io/wedding-seating/
- 工作人員版：同一網址加 `?edit=<編輯金鑰>`（金鑰在本機 `.edit-key`，不進版控）

單一檔案、不需建置，GitHub Pages 直接發佈 `main` 分支。
`.github/workflows/keepalive.yml` 每 3 天讀一次資料庫，避免 Supabase 免費方案閒置暫停。

## 安全

- 名單本來就公開；`seating` schema 不對外開放，只能透過下列 RPC 存取。
- 寫入要帶編輯金鑰；資料庫只存金鑰的 sha256。金鑰外流時，更新 `seating.events.edit_key_hash` 即可換掉。
- 資料表有 CHECK 限制：桌位代號、歸屬值、桌名長度、名單筆數與大小，名單每筆必須是字串。
- 頁面：所有名單內容都經過跳脫再顯示；設定 CSP（只允許自己的程式、Google Fonts、wedding 的 Supabase）與 `no-referrer`（避免帶金鑰的網址外流到其他網站）。

## 用法

- **賓客版**是沉浸式的滿版平面圖（高度 100dvh，大螢幕置中一欄、最寬 720px）：上方浮著「林府文定座位表」與搜尋框，下方是圖例與縮放鈕；不畫牆、門與入口，也不顯示席次一覽。預設放大一級（縮放鈕每級 ×1.3）、對準會場左上；拖曳只到會場邊緣。
- **工作人員版**維持花框卡片：標題 → 固定在頂端的找座位列 → 平面圖 → 席次一覽（電腦上置中，最寬 880px）；手機（≤ 560px）上標題排成左右兩欄、卡片貼滿螢幕，不顯示席次一覽。
- 平面圖：手機單指拖曳、雙指縮放；電腦用滑鼠拖曳、觸控板捏合縮放（賓客版兩指滑動也是平移）。工作人員按在桌子上拖是交換整桌。

- `index.html`：**賓客版**，唯讀。找座位：可搜姓名或桌名（符合的桌子變金色，找不到時下拉清單會說明）；點桌子會從下方浮出桌名與同桌名單。
- 桌機（視窗寬 ≥ 1100px）打開工作人員版時，編輯畫面直接就是輸出版版面（左平面圖、右 7×6 座位表）：點平面圖或右邊的桌卡開啟編輯面板（靠右），拖曳桌子／兒童座椅照常可用。
- `index.html?edit=<編輯金鑰>`：**工作人員版**（金鑰在本機 `.edit-key`，不進版控）。
  - 點桌子開啟編輯面板（手機從下方滑出、電腦置中）：設定桌名（選填，例如「大學同學」）、歸屬（主婚人親友／新人親友）、增刪改賓客。
  - 新增可一次貼上多行，也接受「、」「，」分隔；清空一格或按 × 即移除。
  - **拖曳整桌交換**：把桌子拖到另一桌上（手機要先長按 0.35 秒），桌名、歸屬、賓客整包互換，桌號不動；下方提示可「復原」。
  - **兒童座椅**：平面圖上的綠色方塊，預設放在該桌離走道最遠的一側（朝所在區塊的內側；主桌朝舞台）；可直接拖曳方塊沿桌邊換位置（手機先長按），整桌交換後會重新自動擺放。
  - **素食**：每組賓客另填幾位吃素（編輯面板「素食」欄、新增列與從出席名單加入都會帶入，不超過該組人數）。平面圖上該組的椅子塗成亮黃色圓點（依名單順序，該組前幾張椅子），滑過顯示「素食・姓名」；名單上標「素食 N」，頂端統計顯示總份數。只在工作人員版顯示，賓客版、大圖版與桌卡都不出現。
  - 桌號依平面圖固定：由舞台往入口、由中間往兩側。中左 1–10 → 中右 11–20 → 左區 21–30 → 右區 31–41，每區沿交錯兩欄由上往下；另有主桌。每桌 10 人，超過會標紅。
  - 找座位列下方顯示已安排桌數、賓客人數與同步狀態。

## 輸出版（海報）

`index.html?poster=a2` 是給印刷用的橫式版面：左邊平面圖、右邊 7×6 座位表（41 桌＋圖例），A2（594×420mm），也可 `?poster=a1`、`?poster=a3`。參數要帶紙張尺寸，只寫 `?poster` 會顯示一般網頁版。
手機與網頁版不受影響。

```bash
tools/poster.sh        # → dist/座位表-a2.pdf（讀雲端最新資料）
tools/poster.sh a1     # A1
```

## 桌卡

`index.html?cards` 是 42 張桌卡（主桌＋1–41 桌）的列印版：三角立牌，每面 9×14cm。攤開是一長條（黏貼邊 1.2、底座 5、背面 14、正面 14cm，共 34.2cm；立起來尖頂約 20.6°，每面往後傾約 10°），A3 直式一張並排三條，共 14 張。
正面是「Table」、桌號與桌名（讀雲端最新資料；桌名的數字顯示成全形、空格拿掉，資料不變），背面是感謝文（`TENT_POEM`）；背面倒印，沿頂端對折後兩面都是正的。配色沿用香檳金，拱門框、草寫字（Pinyon Script）、手寫中文（霞鶩文楷 TC）都是程式畫的；底圖是整張水彩（`assets/meadow-bg.jpg`，來自 Pinterest，來源未明、解析度 966×1280），拱門內鋪 60% 的底色讓字清楚。主桌與沒有桌名的桌子，分隔線下方寫 *Reserved*。頁面上方可以切換「預覽版」（每桌正反面並排，背面轉正）和「輸出版」（A3 印刷版面）；不管在哪個檢視按 ⌘P，印出來的都是輸出版。網址會記住：`?cards&view=print`。
預覽後在瀏覽器按 ⌘P →「儲存為 PDF」即可，紙張（A3）與邊界已在頁面設定好。實線是裁切記號、左右留白的虛線是折線（三條同高，一刀壓過整張）。每條左右與下緣有 3mm 出血，相鄰兩條之間留 6mm（各自的出血），雙刀裁切，刀偏 3mm 內都不會切到隔壁；頂端是折線不是裁線，所以沒有出血。建議用 250–300g 卡紙，請影印店裁切、壓折線。工作人員版頂端也有「桌卡 ↗」連結。

## 分享預覽（LINE／FB）

`<head>` 的 Open Graph 標籤讓 LINE 分享時顯示標題、描述與預覽圖 `og.jpg`（1200×630，版型沿用 `../forever-vows` 文定喜帖）；頁面設 `noindex`，不讓搜尋引擎收錄賓客姓名。

```bash
python3 tools/gen-og.py   # → og.jpg、apple-touch-icon.png（需要 ../forever-vows、Pillow、fontTools）
```

LINE 會快取舊的預覽，換圖後分享時網址加 `?v=N`。

## 出席名單匯入

出席調查試算表 → 座位表的「待安排」名單（工作人員編輯面板裡「從出席名單加入」）：

```bash
python3 tools/import_roster.py --dry-run   # 先看統計
python3 tools/import_roster.py             # 上傳
```

- 需要本機 `.sheet-id`（試算表 ID）與 `.edit-key`，兩者都不進版控。
- 只取「能出席」；同名重複回覆保留最後一筆；人數填 0 的先算 1 位並標註「請確認」。
- 只上傳姓名、人數、歸屬、關係、單位、素食、兒童椅；電話與留言不上傳。名單要帶金鑰才讀得到。
- 每一筆是一組賓客：代表人姓名＋這組共幾位＋兒童座椅數＋素食份數（編輯面板裡四個欄位）；人數照實佔座位。已入座的人不會再出現在待安排名單。
- 有新回覆時重跑一次即可，已排好的座位不受影響。

### 試算表已排好的桌次

試算表的兩個排桌分頁（主婚人親友：桌次 1…；新人親友：桌次 A…）可整批放進座位表，B 欄為桌名：

```bash
python3 tools/import_tables.py --dry-run   # 看每一桌會放到第幾桌
python3 tools/import_tables.py             # 寫入（會覆蓋所有桌的桌名、歸屬、名單）
```

主婚人親友依桌次放到第 1… 桌，新人親友接在後面（A→下一號…）；放好後可在工作人員版用拖曳整桌交換位置。

## 資料

存在 Supabase **wedding** 專案（`jkzybhpzihljrluxslmy`）的 `seating` schema，活動代號 `lin-20261025`。
schema 見 `supabase/schema.sql`；`seating` 不對外開放，網頁只透過三個 RPC 存取：

| 函式 | 誰能用 |
|---|---|
| `seating_get(event)` | 所有人（賓客版讀名單） |
| `seating_check_key(event, key)` | 所有人（驗證工作人員網址） |
| `seating_save(event, key, tables)` | 帶正確編輯金鑰的人 |

- 編輯金鑰在資料庫只存 sha256；要換金鑰就更新 `seating.events.edit_key_hash`。
- 工作人員每次修改先存本機 localStorage，0.6 秒後送上雲端；每 15 秒拉一次別人的修改（不會蓋掉自己正在編輯、尚未送出的桌）。
- 賓客版每 60 秒更新一次名單。
- 離線時修改留在本機，恢復連線自動補傳。
