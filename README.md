# wedding-seating

115.10.25 林府文定午宴（聖雅典｜威尼斯 40+2 桌）的席次表網頁。
風格與花框沿用 `../wedding-signs` 的告示牌。

- 賓客版：https://memochou1993.github.io/wedding-seating/
- 工作人員版：同一網址加 `?edit=<編輯金鑰>`（金鑰在本機 `.edit-key`，不進版控）

單一檔案、不需建置，GitHub Pages 直接發佈 `main` 分支。
`.github/workflows/keepalive.yml` 每 3 天讀一次資料庫，避免 Supabase 免費方案閒置暫停。

## 安全

- 名單本來就公開；`seating` schema 不對外開放，只能透過下列 RPC 存取。
- 寫入要帶編輯金鑰；資料庫只存金鑰的 sha256。金鑰外流時，更新 `seating.events.edit_key_hash` 即可換掉。
- 資料表有 CHECK 限制：桌位代號、歸屬值、桌名長度、名單筆數與大小，名單每筆必須是字串。
- 頁面：所有名單內容都經過跳脫再顯示；設定 CSP（只允許自己的程式、Google Fonts、wedding 的 Supabase）與 `no-referrer`（避免帶金鑰的網址外流到其他網站）。

## 用法

版面以手機為主：標題 → 固定在頂端的找座位列 → 平面圖 → 席次一覽（電腦上置中，最寬 880px）。

- `index.html`：**賓客版**，唯讀。找座位：可搜姓名或桌名（符合的桌子變金色）；點桌子會從下方浮出桌名與同桌名單。
- `index.html?edit=<編輯金鑰>`：**工作人員版**（金鑰在本機 `.edit-key`，不進版控）。
  - 點桌子開啟編輯面板（手機從下方滑出、電腦置中）：設定桌名（選填，例如「大學同學」）、歸屬（主婚人親友／新人親友）、增刪改賓客。
  - 新增可一次貼上多行，也接受「、」「，」分隔；清空一格或按 × 即移除。
  - **拖曳整桌交換**：把桌子拖到另一桌上（手機要先長按 0.35 秒），桌名、歸屬、賓客整包互換，桌號不動；下方提示可「復原」。
  - 桌號依平面圖固定：由舞台往入口、由中間往兩側。中左 1–10 → 中右 11–20 → 左區 21–30 → 右區 31–41，每區沿交錯兩欄由上往下；另有主桌。每桌 10 人，超過會標紅。
  - 找座位列下方顯示已安排桌數、賓客人數與同步狀態。

## 出席名單匯入

出席調查試算表 → 席次表的「待安排」名單（工作人員編輯面板裡「從出席名單加入」）：

```bash
python3 tools/import_roster.py --dry-run   # 先看統計
python3 tools/import_roster.py             # 上傳
```

- 需要本機 `.sheet-id`（試算表 ID）與 `.edit-key`，兩者都不進版控。
- 只取「能出席」；同名重複回覆保留最後一筆；人數填 0 的先算 1 位並標註「請確認」。
- 只上傳姓名、人數、歸屬、關係、單位、素食、兒童椅；電話與留言不上傳。名單要帶金鑰才讀得到。
- 每一筆是一組賓客：代表人姓名＋這組共幾位（編輯面板裡兩個欄位）；人數照實佔座位。已入座的人不會再出現在待安排名單。
- 有新回覆時重跑一次即可，已排好的座位不受影響。

### 試算表已排好的桌次

試算表的兩個排桌分頁（主婚人親友：桌次 1…；新人親友：桌次 A…）可整批放進席次表，B 欄為桌名：

```bash
python3 tools/import_tables.py --dry-run   # 看每一桌會放到第幾桌
python3 tools/import_tables.py             # 寫入（會覆蓋所有桌的桌名、歸屬、名單）
```

主婚人親友依桌次放到第 1… 桌，新人親友接在後面（A→下一號…）；放好後可在工作人員版用拖曳整桌交換位置。

## 資料

存在 Supabase **wedding** 專案（`jkzybhpzihljrluxslmy`）的 `seating` schema，活動代號 `lin-20261025`。
schema 見 `supabase/schema.sql`；`seating` 不對外開放，網頁只透過三個 RPC 存取：

| 函式 | 誰能用 |
|---|---|
| `seating_get(event)` | 所有人（賓客版讀名單） |
| `seating_check_key(event, key)` | 所有人（驗證工作人員網址） |
| `seating_save(event, key, tables)` | 帶正確編輯金鑰的人 |

- 編輯金鑰在資料庫只存 sha256；要換金鑰就更新 `seating.events.edit_key_hash`。
- 工作人員每次修改先存本機 localStorage，0.6 秒後送上雲端；每 15 秒拉一次別人的修改（不會蓋掉自己正在編輯、尚未送出的桌）。
- 賓客版每 60 秒更新一次名單。
- 離線時修改留在本機，恢復連線自動補傳。
